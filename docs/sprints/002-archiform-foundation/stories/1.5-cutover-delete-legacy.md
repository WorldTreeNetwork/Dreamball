# Story 1.5: Cutover Commit — Delete `tools/schema-gen/legacy/` and `src/lib/generated.legacy/`

**User Story**: As a release engineer, I want one atomic cutover commit that deletes the legacy generator and its shadow output tree, removes the dual-run wiring from `bun run codegen`, and leaves only the JSON-Schema-driven generator in place, so that the architectural pivot is observable in git history as a single, reversible event with all CI gates green.
**FRs**: FR14, FR1
**Decisions**: D-030 (cutover deletes legacy/ in own commit), TC1, TC2, NFR1
**Complexity**: small
**Test Tier**: thorough

## Acceptance Criteria
- **AC1** [happy — atomic cutover]: Given Story 1.4's shadow phase has been green across at least 3 consecutive PRs (including the merge that lands those PRs), When the cutover commit lands, Then the commit deletes `tools/schema-gen/legacy/` recursively, deletes `src/lib/generated.legacy/` recursively, removes the legacy invocation from `build.zig` schemagen step, and removes the dual-run wiring from `main.zig`'s structured log phases.
- **AC2** [happy — all 7 gates green on the cutover commit]: Given the cutover commit, When the full gate set runs locally (`zig build test`, `zig build smoke`, `bun run check`, `bun run test:unit -- --run`, `scripts/cli-smoke.sh`, `scripts/server-smoke.sh`, `tests/e2e-cryptography.sh`), Then all 7 gates pass per FR14 + TC2 (per `feedback_full_gate_verification`: narrow tests are insufficient).
- **AC3** [grep audit — no legacy refs]: Given the cutover commit, When `grep -R 'generated\.legacy\|tools/schema-gen/legacy\|--mode=legacy' src/ tools/ build.zig package.json` runs, Then results are zero — no dangling references to the deleted paths anywhere in the tree.
- **AC4** [error — rollback path]: Given the cutover commit, When a downstream regression is discovered post-cutover, Then `git revert <cutover-sha>` is the documented rollback (single-commit cutover guarantees this works); rollback restores the shadow-phase state cleanly.

## Technical Notes
- This is intentionally a one-commit story. Smaller is better — the smaller the cutover commit, the safer the revert.
- Pre-cutover checklist (run locally before opening the PR): all 7 gates green; byte-equivalence test green for ≥ 3 PRs in a row; no open issues or warnings in the structured logs from `bun run codegen`.
- The cutover commit message MUST cite NFR1, FR14, and the byte-equivalence verification trail (the shadow-phase PRs that proved equivalence).
- After cutover, Stories 2.1+ may begin (Epic 2 depends on the inverted codegen flow).

## Scope Boundaries
- This story DOES: delete legacy directories and references; run + record full-gate verification; close the FR14 acceptance loop.
- This story does NOT: add per-archiform schema (Epic 2); ship action-manifest changes (Epic 3+); modify any wire-format bytes.
