# Story 3.2: CLI Projection Spike — Project `mint` Verb End-to-End from Action Manifest

**User Story**: As a Dreamball maintainer, I want a spike that projects the `mint` action manifest entry into a generated `jelly palace mint` CLI verb (auto-derived `--help`, flag mapping from `inputs`, JSON output shape from `outputs`, confirmation behavior from `attributes`), with `scripts/cli-smoke.sh` covering `mint` passing against the generated dispatcher, so that the projection generator architecture is validated on one verb before scaling to the remaining four.
**FRs**: FR7
**Decisions**: D-019, D-022 (bridge pattern — generated verb composes Zig staging → Bun bridge → promote-on-success), D-024 (spike before scaling), D-035 (closed sets honored at projection time)
**Complexity**: medium
**Test Tier**: smoke

## Acceptance Criteria
- **AC1** [happy — mint projects from manifest]: Given Story 3.1's authored action manifest, When the new CLI projection generator (`tools/schema-gen/gen_cli.zig` or Bun-side `tools/projections/cli/main.ts` per Phase 3 architectural choice — recorded inline in Dev Agent Record) emits to `src/cli/generated/palace_mint.zig` (or equivalent generated path), Then `jelly palace mint --name foo --mythos-template basic` invokes the generated dispatcher and returns a JSON envelope with shape matching the manifest's `outputs`.
- **AC2** [happy — `--help` derived from manifest]: Given the generated dispatcher, When `jelly palace mint --help` runs, Then output contains the manifest's `summary` text, lists each `inputs.properties.*` as a flag with its declared type, and exits 0.
- **AC3** [happy — bridge pattern composed]: Given a `mint` invocation, When tracing the bridge calls via `JELLY_BRIDGE_DEBUG=1`, Then the trace shows: (i) Bun-side caller computes intended write set, (ii) Zig CLI invoked with `--staging-dir=<tmp>`, (iii) Zig writes envelope to staging, (iv) Bun atomically renames staging into live CAS, (v) ActionLog append happens after promote (per D-022). The generated verb composes this pattern, not bypasses it.
- **AC4** [edge — confirmation behavior]: Given the `mint` manifest entry with `attributes.requiresConfirmation: false`, When `jelly palace mint --name foo --mythos-template basic` runs in a TTY, Then NO prompt is shown; if a future amended manifest sets `requiresConfirmation: true` AND `destructive: true`, the generated verb prompts unless `--yes` / `--no-confirm` is passed (test this via a fixture manifest).
- **AC5** [happy — smoke gate]: Given the generated `palace mint` verb, When `scripts/cli-smoke.sh` runs (mint section), Then it passes with no behavioral regression vs the pre-projection hand-written verb.
- **AC6** [error — manifest drift detected at codegen]: Given the manifest is mutated to remove `inputs.properties.name`, When `bun run codegen` runs, Then either the validator from Story 3.1 rejects (if the change is invalid) OR the regenerated dispatcher's TypeScript compile fails because `--name` is no longer typed; drift cannot land silently.
- **AC7** [grep audit — generated verb in own dir]: Given the spike, When `ls src/cli/generated/` runs, Then `palace_mint.zig` (or the generated equivalent) lives there with NFR9 provenance header; the legacy `src/cli/palace_mint.zig` is preserved for parity until Story 3.5 removes it.

### Architectural commitment (inherited by Stories 3.3–3.5)

Per D-024 spike-before-promote, the choices below are the load-bearing
decisions Stories 3.3–3.5 inherit. Recorded explicitly here so follow-up
agents do not re-litigate them.

1. **Generator location — Zig-side, sibling generator.**
   The CLI projection generator lives at `tools/schema-gen/gen_cli.zig`,
   directly alongside `gen_zig.zig` / `gen_ts.zig` / `gen_valibot.zig` /
   `gen_cbor.zig` / `gen_cypher.zig`. It exposes
   `pub fn generateArchiform(actx: *const gen_cypher.ArchiformCtx) !void`
   matching the per-archiform pass pattern from Story 2.2. The `main.zig`
   orchestrator dispatches to it as the fifth per-archiform target.
   Bun-side projection (Option B in the story planning notes) was rejected
   because it would split the codegen toolchain in two, violating the
   D-018 / D-030 single-pipeline invariant. *No new toolchain.*

2. **Output path — `src/cli/generated/palace_<snake>.zig`.**
   `<snake>` is the kebab verb name with `-` rewritten to `_` (e.g.
   `add-room` → `add_room`, `rename-mythos` → `rename_mythos`). The
   directory `src/cli/generated/` is the canonical home for projected
   verbs; `src/cli/palace_<snake>.zig` (legacy) coexists during the
   spike-and-port window per Story 3.5's eventual deletion path.

3. **Flag mapping — manifest-keys verbatim, kebab-as-typed.**
   Each `inputs.properties.<key>` becomes an `args_mod.Spec{ .long = "<key>" }`.
   Boolean-typed properties become `takes_value = false`; everything else
   takes a value. The manifest's key naming is the authority: `mythosFile`
   stays `--mythosFile`, `add-room` style hyphenation stays hyphenated.
   Synthetic flags `--yes` and `--no-confirm` (confirmation-bypass) and
   `--help` are appended to every dispatcher's SPECS table.
   Required-flag enforcement is emitted from `inputs.required` and uses
   the legacy-compatible message shape `error: <flag> required\n`
   (deliberate choice — the substring is what `scripts/cli-smoke.sh`
   already greps; preserving the shape avoids a parallel rewrite of
   smoke checks for every projected verb).

4. **Confirmation gate — emitted only when both flags true.**
   The dispatcher emits the confirmation block (read message, demand
   `--yes` / `--no-confirm`, `return 2` on refusal) **only** when
   `attributes.destructive == true` AND `attributes.requiresConfirmation == true`.
   When either is false the gate is omitted entirely (no dead branches in
   the generated source). This binary behavior is covered by 4 inline
   tests in `gen_cli.zig` (AC4 fixture-mode tests).

5. **Bridge composition — dispatcher delegates to legacy `pub fn run`.**
   The generated dispatcher is **flag-parse + help + confirmation only**;
   it does not re-implement the bridge primitive (D-022 staging → bun
   bridge → promote-on-success → ActionLog append). After its own parse
   it calls `legacy.run(gpa, argv)` from `src/cli/palace_<snake>.zig`,
   which retains the full bridge composition. This is the spike's
   smallest viable diff: the projection layer adds the manifest-driven
   policing without disturbing the proven bridge invariant.
   Story 3.5's eventual cutover inlines the bridge body into the
   generated source and deletes the legacy file.

### Problems encountered

1. **Stale Zig build cache.** First `zig build` invocation surfaced an
   `embed of file outside package path: '../schemas/...'` error in
   `src/archiform.zig` (a Story 2.3 file). The actual on-disk source
   used the symlink path `schemas/memory-palace-0.1.0.json` (i.e. via
   `src/schemas` → `../schemas`); Zig was reporting the cached pre-fix
   form. `rm -rf .zig-cache` followed by a clean build resolved it.
   No code change needed; documenting here so the next agent that hits
   it knows the cache, not the source, was the issue.

2. **`std.json.Array` / `ObjectMap` builder API friction in Zig 0.16.**
   First-cut test helpers used `std.json.ObjectMap.init(arena)` (one
   arg) — the 0.16 API is `init(gpa, key_list, value_list)`. Pivoted
   the AC4 fixture builder to construct manifests by formatting a
   templated JSON string and parsing it with
   `std.json.parseFromSliceLeaky`; cleaner, less API-version-coupled.

3. **`std.ArrayList(u8).writer(arena).print(...)` is not a method on
   the unmanaged ArrayList in Zig 0.16.** Pivoted to building format
   strings with `std.fmt.allocPrint` and `appendSlice`-ing them into
   the body buffer.

4. **Smoke-script substring expectation for missing-flag errors.** The
   first generator pass emitted `error: --mythos is required\n` which
   broke `grep -q "mythos required"` in `scripts/cli-smoke.sh`. Per the
   architectural commitment in §1, the canonical message shape is
   `error: <flag> required\n` (legacy-compatible substring). Generator
   updated; smoke green.
