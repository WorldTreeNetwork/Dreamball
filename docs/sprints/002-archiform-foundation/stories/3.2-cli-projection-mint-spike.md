# Story 3.2: CLI Projection Spike — Project `mint` Verb End-to-End from Action Manifest

**User Story**: As a Dreamball maintainer, I want a spike that projects the `mint` action manifest entry into a generated `jelly palace mint` CLI verb (auto-derived `--help`, flag mapping from `inputs`, JSON output shape from `outputs`, confirmation behavior from `attributes`), with `scripts/cli-smoke.sh` covering `mint` passing against the generated dispatcher, so that the projection generator architecture is validated on one verb before scaling to the remaining four.
**FRs**: FR7
**Decisions**: D-019, D-022 (bridge pattern — generated verb composes Zig staging → Bun bridge → promote-on-success), D-024 (spike before scaling), D-035 (closed sets honored at projection time)
**Complexity**: medium
**Test Tier**: smoke

## Acceptance Criteria
- **AC1** [happy — mint projects from manifest]: Given Story 3.1's authored action manifest, When the new CLI projection generator (`tools/schema-gen/gen_cli.zig` or Bun-side `tools/projections/cli/main.ts` per Phase 3 architectural choice — recorded inline in Dev Agent Record) emits to `src/cli/generated/palace_mint.zig` (or equivalent generated path), Then `jelly palace mint --name foo --mythos-template basic` invokes the generated dispatcher and returns a JSON envelope with shape matching the manifest's `outputs`.
- **AC2** [happy — `--help` derived from manifest]: Given the generated dispatcher, When `jelly palace mint --help` runs, Then output contains the manifest's `summary` text, lists each `inputs.properties.*` as a flag with its declared type, and exits 0.
- **AC3** [happy — bridge pattern composed]: Given a `mint` invocation, When tracing the bridge calls via `JELLY_BRIDGE_DEBUG=1`, Then the trace shows: (i) Bun-side caller computes intended write set, (ii) Zig CLI invoked with `--staging-dir=<tmp>`, (iii) Zig writes envelope to staging, (iv) Bun atomically renames staging into live CAS, (v) ActionLog append happens after promote (per D-022). The generated verb composes this pattern, not bypasses it.
- **AC4** [edge — confirmation behavior]: Given the `mint` manifest entry with `attributes.requiresConfirmation: false`, When `jelly palace mint --name foo --mythos-template basic` runs in a TTY, Then NO prompt is shown; if a future amended manifest sets `requiresConfirmation: true` AND `destructive: true`, the generated verb prompts unless `--yes` / `--no-confirm` is passed (test this via a fixture manifest).
- **AC5** [happy — smoke gate]: Given the generated `palace mint` verb, When `scripts/cli-smoke.sh` runs (mint section), Then it passes with no behavioral regression vs the pre-projection hand-written verb.
- **AC6** [error — manifest drift detected at codegen]: Given the manifest is mutated to remove `inputs.properties.name`, When `bun run codegen` runs, Then either the validator from Story 3.1 rejects (if the change is invalid) OR the regenerated dispatcher's TypeScript compile fails because `--name` is no longer typed; drift cannot land silently.
- **AC7** [grep audit — generated verb in own dir]: Given the spike, When `ls src/cli/generated/` runs, Then `palace_mint.zig` (or the generated equivalent) lives there with NFR9 provenance header; the legacy `src/cli/palace_mint.zig` is preserved for parity until Story 3.5 removes it.

## Technical Notes
- Per D-024, this is THE spike for Cluster C. The architectural commitment from this story (generator location: Zig vs Bun-side; output path; flag-mapping conventions) is what Stories 3.3–3.5 inherit. Decisions made here are recorded inline in the Dev Agent Record AND, if cross-epic, escalated to an ADR amendment (per D-025).
- Per `feedback_dreamball_ac_scope_retreat`: if the spike hits a blocker (e.g., manifest's `outputs` shape can't be expressed in Zig types without a missing primitive), raise the blocker — do NOT silently substitute a hand-written verb that *looks* generated.
- Per D-022, the bridge-pattern composition in the generated verb mirrors the existing 5 examples in `src/lib/bridge/palace-{mint,...}.ts`. The generator emits Zig that calls into the same bridge primitives.
- The hand-written `src/cli/palace_mint.zig` stays in place for parity verification during this story; Story 3.5 removes it after all 5 verbs project cleanly.
- Per IC2: the envelope produced by the generated verb serializes to the existing signed-action envelope shape — no new top-level fields.

## Scope Boundaries
- This story DOES: project ONE verb (`mint`) end-to-end; ship the projection generator architecture; verify smoke; record the architectural commitment.
- This story does NOT: project the other 4 verbs (Stories 3.3–3.4); remove hand-written stubs (Story 3.5); ship TS client / MCP projections (Epic 4); ship wasm action implementations (Epic 5).
