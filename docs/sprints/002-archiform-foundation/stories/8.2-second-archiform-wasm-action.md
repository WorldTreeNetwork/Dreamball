# Story 8.2 [STRETCH]: Author + Run Guestbook Wasm Action End-to-End Through Host

**User Story**: As an archiform author, I want a tiny `sign.wasm` (or equivalent) for the guestbook archiform that runs end-to-end through the same wasm host (no host changes), proving the host generalizes beyond Memory Palace, so that the federation hypothesis is exercised on the runtime side as well as the codegen side.
**FRs**: (no FRs — integration test of Cluster E manifold)
**Decisions**: D-019, D-020, D-022, D-023, D-031 (transitive trust), D-033 (only the locked 5 imports — no new ones)
**Complexity**: medium
**Test Tier**: thorough

## Acceptance Criteria
- **AC1** [happy — wasm action exists + fp pinned]: Given the guestbook schema from Story 8.1, When `zig build guestbook-sign-wasm` compiles, Then `actions/guestbook/sign.wasm` exists; `blake3(sign.wasm)` is recorded as the `implementation.wasm` field in `schemas/guestbook-0.1.0.json` for the `sign` action; pin file updates via `bun run schemas:pin`.
- **AC2** [happy — runs through host with NO host changes]: Given Stories 5.2/5.3/5.4's wasm host, When `jelly` invokes the `sign` action via the same host code that runs `mint.wasm`, Then `sign.wasm` executes its `sign` export, calls `dreamball.emit_action_envelope`, and produces a host-signed envelope; the Dev Agent Record explicitly confirms NO changes to `src/wasm-host/*` were required.
- **AC3** [happy — uses only the locked 5 imports per D-033]: Given `sign.wasm`, When `wasm-tools` dumps the import table, Then every import is one of the 5 locked names; no novel imports appear; AC fails if a 6th is needed (raise blocker per `feedback_dreamball_ac_scope_retreat`).
- **AC4** [happy — verify-before-instantiate exercised]: Given the manifest's pinned `implementation.wasm` fp, When the host loads `sign.wasm`, Then Story 5.3's blake3 verify fires and emits `{phase: "verify", status: "match", module_fp}` BEFORE instantiation.
- **AC5** [perf — TC5 size soft target]: Given `sign.wasm`, When `stat` runs, Then size < 1 MB (per TC5 soft target).
- **AC6** [error — guest cannot forge signature per SEC2]: Given a malicious guest variant under `tests/wasm/guestbook-malicious/`, When the variant attempts to compose its own signature bytes (no key access), Then the produced envelope's signature fails verification; per SEC2.
- **AC7** [happy — full gate set green]: Given the new wasm action, When the full gate set runs, Then all 7 gates pass — confirms the host generalizes without regressions.

## Technical Notes
- "No host changes" (AC2) is the explicit federation-proof success criterion. If the host needs ANY change to support the guestbook action, the change is itself an architectural finding to surface — it means Memory Palace's idiosyncrasies leaked into the host.
- Per D-031: bug-fixing `sign.wasm` requires schema reissue (recompute pin, update `schemas/guestbook-0.1.0.json`'s manifest). Document this as the natural lifecycle event.
- Per IC2: the produced envelope serializes to the existing signed-action envelope shape — no new envelope fields for guestbook.
- Per `feedback_dreamball_ac_scope_retreat`: if the wasm needs primitives outside the 5 locked imports, raise blocker. Resolution is ADR amendment to D-033 — but in Cluster I scope the expected outcome is "the 5 imports were sufficient" and that IS the federation proof.

## Scope Boundaries
- This story DOES: ship `actions/guestbook/sign.wasm`; pin its fp; run end-to-end through the host with NO host changes; full gate green; signature-forgery rejection.
- This story does NOT: project to CLI (Story 8.3); add wasm modules for any action other than `sign`; modify the host (the WHOLE point is to NOT need to).
