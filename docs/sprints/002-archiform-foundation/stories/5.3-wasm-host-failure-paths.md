# Story 5.3: Wasm Host Failure Paths — Verify-Before-Instantiate, Import-Violation, Memory-Limit

**User Story**: As a CI gate, I want the wasm host to enforce three failure paths — verify-before-instantiate (blake3 mismatch aborts), import-violation (any import outside `dreamball.*` rejected), memory-limit (16 MiB initial / 64 MiB hard ceiling; OOM traps to projection-layer error) — each with structured failure events, so that SEC1, SEC4, and NFR7 become tested invariants of the host rather than aspirational claims.
**FRs**: FR10, FR11
**Decisions**: D-020 (wasm runtime), D-031 (verify-before-instantiate is blake3-only per SEC4), D-033 (locked import surface), SEC1 (host-import whitelist), SEC4 (verify-before-instantiate), NFR7 (memory budget), NFR11 (structured events for failure outcomes)
**Complexity**: medium
**Test Tier**: thorough

## Acceptance Criteria
- **AC1** [happy — verify-before-instantiate per SEC4]: Given a wasm module bytes B and an action manifest declaring `implementation.wasm: <fp>`, When the host attempts instantiation and `blake3(B) == fp`, Then instantiation proceeds; When `blake3(B) ≠ fp`, Then instantiation aborts BEFORE any guest code runs and a structured failure event is emitted with `{outcome: "fp_mismatch", expected, actual, module_fp}` (per NFR11).
- **AC2** [happy — import-violation per SEC1]: Given a guest module that imports `env.malicious_function` (or any name outside `dreamball.*`), When the host validates imports at module load, Then validation fails BEFORE instantiation; structured event emits `{outcome: "import_violation", offending_import, module_fp}`.
- **AC3** [happy — memory-limit default per NFR7]: Given a guest module instantiated with default settings, When inspected, Then initial linear memory is 16 MiB; the hard ceiling is 64 MiB.
- **AC4** [happy — memory-limit configurable per FR10]: Given the CLI flag `--wasm-mem-mib 32`, When the host instantiates a guest, Then initial memory is 32 MiB; ceiling stays at 64 MiB; values exceeding 64 MiB are rejected at CLI parse time with a clear error.
- **AC5** [edge — OOM traps to projection-layer error per NFR7]: Given a guest that allocates beyond the 64 MiB ceiling, When the allocation occurs, Then the wasm runtime traps; the host catches the trap and surfaces a structured error event `{outcome: "trap", trap_kind: "oom", module_fp, attempted_alloc_bytes}`; the projection layer (CLI) emits a clean exit with non-zero code.
- **AC6** [edge — symmetric application to all hosts]: Given the failure-path implementations, When `grep -RE 'verifyBlake3|verifyImports|checkMemoryLimit' src/wasm-host/` runs, Then the verification helpers live in the shared host source (per D-032), not duplicated per platform; per SEC4: "applies symmetrically to CLI, jelly-server, and in-renderer hosts."
- **AC7** [structured events on every failure per NFR11]: Given any of AC1/AC2/AC5 failures, When the failure occurs, Then a single structured-log JSON event is emitted on stderr matching the schema declared in Story 5.2 AC7 (with `outcome` taking the failure-mode value).
- **AC8** [happy — fp-mismatch test fixtures]: Given a fixture wasm module + a deliberately-wrong fp, When `tests/wasm/host/fp-mismatch.test.ts` runs, Then the host rejects per AC1 with the expected event; analogous fixtures for import-violation (AC2) and OOM (AC5) live under the same directory.

## Technical Notes
- Per D-031: SEC4 verification is blake3-only — no per-module signature check needed in sprint-002 (trust chain is "publisher signs schema → schema body declares wasm fp → blake3 verifies wasm bytes"). This story implements the blake3 leg only.
- Memory-limit enforcement leans on the chosen runtime's memory-limit primitives (Story 5.1 selected the runtime; if the runtime can't enforce hard ceilings natively, raise a blocker per `feedback_dreamball_ac_scope_retreat`).
- The 16 MiB / 64 MiB numbers are NFR7 defaults — DO NOT introduce different defaults without ADR amendment (per D-025).
- Import-validation happens BEFORE instantiation: walk the wasm module's import table, check each `(module, field)` pair against the allowlist (`dreamball.*` only), reject before any code runs. This is a static check; no guest code executes during validation.
- `--wasm-mem-mib` is a CLI flag on the projection layer (Story 5.2 added the host; this story adds the CLI surface).

## Scope Boundaries
- This story DOES: ship verify-before-instantiate; ship import-violation rejection; ship memory-limit enforcement (default + configurable + OOM trap); ship structured failure events; ship fixture tests for each failure mode.
- This story does NOT: ship sample `mint.wasm` end-to-end (Story 5.4); author `docs/dreamball-imports.md` (Story 5.5); add per-projection permissions (sprint-003 per Q10); implement per-module signing (deferred per D-031 — blake3-only this sprint).
