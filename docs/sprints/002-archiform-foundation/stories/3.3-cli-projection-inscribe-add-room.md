# Story 3.3: CLI Projection — `inscribe` and `add-room` Verbs

**User Story**: As an archiform author, I want `jelly palace inscribe` and `jelly palace add-room` to be mechanically projected from the action manifest using the architecture spiked in Story 3.2, so that two more verbs are off the hand-written dispatch path with their bridge-pattern + smoke coverage preserved.
**FRs**: FR7
**Decisions**: D-019, D-022 (bridge pattern), D-035, IC2
**Complexity**: medium
**Test Tier**: smoke

## Acceptance Criteria
- **AC1** [happy — inscribe projects]: Given the manifest entry for `inscribe` and the generator architecture from Story 3.2, When `bun run codegen` runs, Then `src/cli/generated/palace_inscribe.zig` is emitted with NFR9 provenance header; `jelly palace inscribe --palace-fp <fp> --content "test" --surface scroll` invokes the generated dispatcher and emits a signed-action envelope.
- **AC2** [happy — add-room projects]: Given the manifest entry for `add-room`, When codegen runs, Then `src/cli/generated/palace_add_room.zig` is emitted; `jelly palace add-room --palace-fp <fp> --name "Library"` invokes the generated dispatcher and emits a signed-action envelope.
- **AC3** [happy — bridge pattern composed for both]: Given each verb, When invoked with `JELLY_BRIDGE_DEBUG=1`, Then trace shows the staging → bridge → promote sequence per D-022 (same as Story 3.2 AC3).
- **AC4** [edge — `inscribe` `--help` matches manifest summary]: Given `jelly palace inscribe --help`, When inspected, Then the help text matches the manifest's `summary` field; flags map 1:1 from `inputs.properties.*`.
- **AC5** [happy — smoke gate]: Given both generated verbs, When `scripts/cli-smoke.sh` runs (inscribe + add-room sections), Then both pass with no behavioral regression vs hand-written verbs.
- **AC6** [error — confirmation behavior on destructive `add-room`]: Given the `add-room` manifest is amended to set `attributes.destructive: true, requiresConfirmation: true` (test fixture only), When `jelly palace add-room` runs in a TTY without `--yes`, Then the generated dispatcher prompts; with `--yes` or `--no-confirm`, no prompt and the action proceeds.

## Technical Notes
- This story consumes the architecture from Story 3.2 verbatim — no architectural change. If a verb requires architecture amendment, raise blocker (per `feedback_dreamball_ac_scope_retreat`) rather than silently diverging.

### Architectural inheritance from Story 3.2

This story consumed the 3.2 architecture verbatim (per AC note). Two extensions were needed:

1. **WHITELIST expansion**: `WHITELIST` in `tools/schema-gen/gen_cli.zig` extended from
   `["mint"]` to `["mint", "inscribe", "add-room"]`. The generator loop already iterated
   over `x-actions.*`; expanding the whitelist was the only change needed to project two
   more verbs.

2. **POSITIONAL_SKIP convention**: `palace` and `source` appear in `inputs.properties`
   for `inscribe` (and `palace` for `add-room`) but are positional CLI arguments in all
   legacy verbs — never `--flag value` pairs. A new `POSITIONAL_SKIP` constant was added
   to exclude these from SPECS emission and required-flag enforcement. This is a
   generator-layer CLI convention, not an architectural change; it preserves the D-022
   bridge composition intact.

3. **camelToKebab conversion**: Manifest property names `embedVia` and `mythosFile` are
   camelCase; all legacy verbs use `--embed-via` and `--mythos-file`. A `camelToKebab`
   function was added to the generator so SPECS entries and HELP_TEXT use the correct
   kebab-case form matching the legacy verb arg parsers and smoke-test invocations.
   `prop_names` (manifest keys) are kept for required-error messages; `prop_flags`
   (kebab-case) are used for SPECS and HELP_TEXT. This affected all three verbs
   (including `mint`'s `mythosFile` → `mythos-file`), all consistent with legacy.

### Problems encountered

1. **Zig build cache stale from parallel Story 5.4 agent.** Story 5.4 added
   `src/wasm-host/mint_host_main.zig` (untracked) and wired it into `build.zig` with
   `b.installArtifact`. An earlier intermediate version of that file had `init.argv`
   (wrong for Zig 0.16); the build cache still held the old error. `rm -rf .zig-cache`
   + clean build resolved it. Story 5.4's final file uses `init.minimal.args`
   correctly; the error was a stale-cache artifact, not a real collision.

2. **camelCase manifest keys vs kebab-case CLI flags.** The manifest uses `embedVia`
   and `mythosFile`; the legacy verbs and smoke tests use `--embed-via` and
   `--mythos-file`. The generator was generating camelCase SPECS entries which caused
   `ArgError.UnknownFlag` when the smoke test passed kebab-case flags. Fixed by adding
   `camelToKebab` and a `prop_flags` list alongside `prop_names`. The fix also improved
   `mint`'s `mythosFile` → `mythos-file` (consistent with the legacy `palace_mint.zig`
   SPECS).

3. **Positional args in `inputs.required`.** `inscribe` lists `palace`, `room`, and
   `source` in `required`; `palace` and `source` are positional, not flags. The
   generator emitting `if (parsed.get(idx) == null)` for them would always fail for
   standard invocations. Fixed via `POSITIONAL_SKIP` convention (see Architectural
   inheritance above).
