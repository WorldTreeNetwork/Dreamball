# Story 5.5: Author `docs/dreamball-imports.md` Enumerating the 5-Import Surface

**User Story**: As an archiform author, I want `docs/dreamball-imports.md` to enumerate all 5 sprint-002 `dreamball.*` imports with arity, types, error semantics, and host-trust notes, so that future archiform authors have a single canonical reference for the host-import contract and the surface cannot drift silently per D-033.
**FRs**: FR11, FR15 (partial — the doc itself; broader doc refresh is Epic 7)
**Decisions**: D-025 (forward-declare contracts), D-033 (lock surface to 5; doc IS the contract artifact), SEC2 (host-mediated signing trust note)
**Complexity**: small
**Test Tier**: smoke

## Acceptance Criteria
- **AC1** [happy — doc exists with all 5 imports]: Given the file `docs/dreamball-imports.md`, When inspected, Then it documents exactly 5 imports: `dreamball.fp`, `dreamball.encode_cbor`, `dreamball.read_node`, `dreamball.emit_action_envelope`, `dreamball.now_ms` — each with arity (parameter count + types), return type, error semantics, and host-trust note.
- **AC2** [happy — host-trust notes per SEC2]: Given the doc, When the `emit_action_envelope` entry is read, Then the host-trust note explicitly states: "the host signs using the actor keypair; the wasm body cannot forge signatures because it has no access to private key material" (per SEC2).
- **AC3** [happy — error semantics tabulated]: Given each import, When the doc's error-semantics column is read, Then it names the trap kinds the host emits for that import (e.g., `dreamball.fp` may trap on `bytes_len > guest_memory_size`; `dreamball.read_node` traps on `node_not_found`; etc.) — matching the structured-event `outcome` enum from Story 5.2 AC7.
- **AC4** [grep audit — doc enumerates exactly 5]: Given `docs/dreamball-imports.md`, When `grep -cE '^### `dreamball\\.' docs/dreamball-imports.md` runs, Then the count is exactly 5; per D-033's locked surface.
- **AC5** [happy — D-033 amendment process documented]: Given the doc, When the "Adding a new import" section is read, Then it explicitly states that any new import requires a new architecture-decision entry (D-NNN amendment) per D-025 + D-033, NOT a story-execution event.
- **AC6** [happy — markdown lint + link check]: Given the doc, When `bun run lint:md` (or equivalent — markdownlint) and a link checker run, Then both pass; broken links fail CI.

## Technical Notes
- This story produces the doc artifact; Epic 7 (Story 7.1 in particular) folds it into the broader doc refresh (PROTOCOL.md cross-references, ARCHITECTURE.md citations).
- Format the import entries consistently — each as `### dreamball.<name>` with subsections for Signature, Returns, Errors, Trust. This makes machine-grep audits (AC4) reliable.
- If `bun run lint:md` doesn't exist yet, add it to `package.json` (one-line script) — markdown linting is part of Cluster H's smoke surface.
- Per D-033: the doc IS the locked surface contract. If a new import is needed mid-sprint, this doc updates as part of an ADR amendment, NOT as part of an action-implementation story.

## Scope Boundaries
- This story DOES: ship `docs/dreamball-imports.md` with all 5 import entries + amendment-process section + markdown lint pass.
- This story does NOT: rewrite ARCHITECTURE.md (Story 7.2); update PROTOCOL.md trust-model section (Story 7.1); change the wasm host code (Stories 5.2–5.4 are the implementation owners).
