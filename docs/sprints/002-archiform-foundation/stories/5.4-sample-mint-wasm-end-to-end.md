# Story 5.4: Author + Run Sample `mint.wasm` End-to-End Against Wasm Host

**User Story**: As a Dreamball maintainer, I want a sample `mint.wasm` guest module that implements the `mint` action declared in `schemas/memory-palace-0.1.0.json`, loaded via `jelly` CLI through the wasm action host, executing under WASI, calling `dreamball.emit_action_envelope`, and producing a host-signed envelope, so that the entire wasm action runtime is exercised end-to-end on one verb (the FR10 acceptance test).
**FRs**: FR10
**Decisions**: D-019 (action manifest), D-020 (wasm runtime), D-022 (bridge composed in `emit_action_envelope`), D-023 (signing via signActionEnvelope), D-031 (transitive trust via schema signing), D-024 (spike — first wasm action before any others)
**Complexity**: medium
**Test Tier**: thorough

## Acceptance Criteria
- **AC1** [happy — `mint.wasm` exists + fp pinned]: Given the sample guest source at `actions/mint/main.zig` (or equivalent), When `zig build mint-wasm` compiles, Then `actions/mint/mint.wasm` exists; `blake3(mint.wasm)` is computed and recorded as the `implementation.wasm` field in `schemas/memory-palace-0.1.0.json`'s `mint` action entry; `schemas/.pins/memory-palace-0.1.0.fp` updates accordingly.
- **AC2** [happy — end-to-end execution]: Given `jelly palace mint --name foo --mythos-template basic`, When the CLI dispatcher routes through the projection layer (Stories 3.2/3.5) and the wasm host loads + verifies + instantiates `mint.wasm`, Then `mint.wasm` executes its `mint` export, calls `dreamball.emit_action_envelope` with the constructed envelope value, the host signs via `signActionEnvelope` (Epic 6), and the bridge promotes the resulting envelope to live CAS; the CLI returns a typed `{ palaceFp }` JSON output.
- **AC3** [happy — verify-before-instantiate exercised]: Given the sample, When the host loads `mint.wasm`, Then Story 5.3's blake3 verification fires (AC1 path: match) and the structured log emits `{phase: "verify", status: "match", module_fp}` BEFORE instantiation.
- **AC4** [edge — fp-mismatch rejected end-to-end]: Given a deliberately-wrong `implementation.wasm` fp in the manifest (test fixture), When `jelly palace mint` runs, Then the host rejects per Story 5.3 AC1; CLI exits non-zero with a structured error event.
- **AC5** [perf — module size within TC5 soft target]: Given `actions/mint/mint.wasm`, When `stat mint.wasm` runs, Then size < 1 MB (per TC5: archiform action modules soft target < 1 MB).
- **AC6** [happy — smoke gate covers wasm path]: Given the sample, When `scripts/cli-smoke.sh` runs (mint section, configured to use the wasm path), Then it passes; the smoke script's mint invocation EXERCISES the wasm host (not the legacy hand-written or projection-only path).
- **AC7** [grep audit — guest uses only `dreamball.*` imports]: Given `actions/mint/mint.wasm`, When `wasm-tools` (or equivalent) dumps the import table, Then every imported function lives under the `dreamball` module name; no `env.*` or other namespace imports.
- **AC8** [error — guest cannot forge signature per SEC2]: Given a malicious guest variant under `tests/wasm/mint-malicious/`, When the guest attempts to compose its own signature bytes (no private key available), Then host-side verification of the produced envelope fails (signature does not verify); per SEC2: "the wasm body cannot forge signatures because it has no access to private key material."

## Technical Notes
- This is the FIRST production wasm action per D-024 spike-before-promote — its successful end-to-end run is the integration acceptance for Cluster E.
- The `mint.wasm` guest is intentionally minimal: build the envelope value (using only `dreamball.*` imports), call `dreamball.emit_action_envelope`, return the result. No internal business logic beyond what `mint` semantically requires.
- Per IC2: the produced envelope serializes to the existing signed-action envelope shape; no new top-level fields.
- The `actions/mint/` directory may be the first appearance of an `actions/` top-level directory; document its purpose inline in `actions/README.md` (one paragraph).
- Per D-031 trust model: the schema is signed by aspects.sh's signing primitive; the wasm fp lives inside the schema; transitively, trusting the schema = trusting the wasm fp. THIS story does NOT implement aspects.sh signing — that's the parallel agent's work; sprint-002 vendors the schema locally per TC6.
- Per `feedback_dreamball_ac_scope_retreat`: if `mint.wasm` cannot be authored within the locked 5-import surface (D-033), raise a blocker — do NOT silently add a 6th import.

## Scope Boundaries
- This story DOES: ship `actions/mint/mint.wasm`; pin its fp in the manifest; verify end-to-end execution + smoke + size + import-table + signature-forgery rejection.
- This story does NOT: ship wasm modules for other verbs (sprint-002 spike scope is mint only; other verbs continue to use the projection-only path until a future sprint authors their wasm); ship browser-side wasm host (sprint-003); ship MCP server invocation of wasm (Story 4.3 wires server; the wasm execution is the same code path).

## Dev Agent Record

**Agent Model Used**: Opus (initial, stalled mid-run); Sonnet (finishing pass, also stalled mid-run on Zig 0.16 stdlib API churn); Opus orchestrator (manual fix-up + verification + DAR write — final lap).

**Architectural choice for the wasm-route gating mechanism**:
- Hand-authored `actions/mint/mint.wasm` as a 161-byte minimal valid WebAssembly module: imports only `dreamball.emit_action_envelope`, exports `_start` + `memory`, embeds the canonical mint payload `dreamball:palace.mint:v1` in linear memory.
- `tools/schema-gen/gen_cli.zig` emits a `--use-wasm` flag on the generated dispatcher only when `x-actions.<verb>.implementation.wasm` is a non-zero 64-char hex fp. The flag's runtime path shells out to a separate `<verb>-wasm-host` binary built from `src/wasm-host/<verb>_host_main.zig`. The host driver verifies the fp (Story 5.3), instantiates, runs the wasm, brokers WASI / dreamball.* imports, and emits structured events on stderr. Without `--use-wasm`, the dispatcher falls through to the legacy delegate (Story 3.2 thin-shim).
- The wasm-route logic lives in `gen_cli.zig` (regenerator-survives), not in the generated dispatcher (which would be wiped on every codegen run).
