# Story 3.1: Action Manifest Schema in Memory Palace JSON Schema + Closed-Set Validator + Pure-Transaction Lint

**User Story**: As an archiform author, I want the action-manifest section of `schemas/memory-palace-0.1.0.json` to declare every sprint-001 verb with closed `attributes` keys (`destructive`, `requiresConfirmation`, `confirmationMessage`, `agentVisible`) and closed `effects.kind` enum (`ActionEnvelope`, `Read`, `Derived`), with the generated Valibot validator rejecting unknown keys/values and a "pure-transaction" lint rejecting interactive input fields, so that every projection (CLI/programmatic/MCP) inherits one mechanically-checkable contract.
**FRs**: FR6
**Decisions**: D-019 (action manifest as universal contract; pure transactions only), D-025 (cross-epic contract locked here), D-035 (closed sets), D-024 (spike before scaling — this story authors all 5 verb manifests; Story 3.2 spikes the projection of one)
**Complexity**: medium
**Test Tier**: smoke

## Acceptance Criteria
- **AC1** [happy — manifest authored for all 5 verbs]: Given `schemas/memory-palace-0.1.0.json`, When the `actions` map is authored, Then it declares one entry per sprint-001 verb (`mint`, `inscribe`, `add-room`, `rename-mythos`, `move`) — each with `summary`, `inputs`, `outputs`, `effects`, `idempotency`, `streaming`, `attributes`, and `implementation` (sprint-002: `wasm` only); the schema validates against draft 2020-12 metaschema and Story 2.1's pin updates accordingly.
- **AC2** [happy — closed `attributes` per D-035]: Given the regenerated Valibot validator from `gen_valibot.zig`, When a manifest with attribute `{destructive: true, requiresConfirmation: true, confirmationMessage: "...", agentVisible: true}` is parsed, Then validation passes; When a manifest with `{destructive: true, x-experimental: true}` is parsed, Then validation rejects with `"unknown attribute: x-experimental"` (sprint-002 rejects `x-` prefix entirely per D-035).
- **AC3** [happy — closed `effects.kind` enum per D-035]: Given the validator, When `effects.kind: "ActionEnvelope"` / `"Read"` / `"Derived"` are parsed, Then all pass; When `effects.kind: "Mutation"` is parsed, Then validation rejects with `"unknown effects.kind: Mutation"`.
- **AC4** [happy — closed `idempotency` enum]: Given the validator, When `idempotency` is `"creates"` / `"updates"` / `"idempotent"`, Then all pass; When `idempotency: "rerunnable"` is parsed, Then validation rejects with `"unknown idempotency value: rerunnable"`.
- **AC5** [edge — pure-transaction lint per FR6]: Given a manifest with `inputs.properties.confirm: {type: "boolean"}`, When the pure-transaction lint runs (new Vitest at `tests/codegen/pure-transaction-lint.test.ts`), Then the lint rejects naming the field; same for fields named `prompt` or having `format: "tty-interactive"`; passing manifests pass.
- **AC6** [error — non-fp `implementation.wasm`]: Given a manifest with `implementation.wasm: "https://example.com/mint.wasm"` (URL not fp), When the validator runs, Then validation rejects requiring `implementation.wasm` to match the blake3-hex pattern (64 hex chars).
- **AC7** [pin updates correctly]: Given the schema is amended with action manifest entries, When `bun run schemas:pin schemas/memory-palace-0.1.0.json` runs, Then `schemas/.pins/memory-palace-0.1.0.fp` updates to the new blake3; subsequent `bun run codegen` invocations verify successfully.
- **AC8** [grep audit — no hand-written manifests elsewhere]: Given the manifest authored, When `grep -RE 'attributes:\\s*\\{|effects:\\s*\\{\\s*kind:' src/cli/ src/lib/bridge/ tools/ --include='*.ts' --include='*.zig'` runs (excluding `src/lib/generated/` and `tools/schema-gen/`), Then results are zero — manifests live only in JSON Schema, not duplicated in code.

## Technical Notes
- This story is the *contract authoring* story; Story 3.2 spikes the projection (mint verb end-to-end). Per D-024, the contract MUST be locked here before projection scaling.
- Per D-025, the action manifest shape is a cross-epic contract consumed by Epics 4 (TS client + MCP) and 5 (wasm host). Adding new attribute/effect.kind values mid-sprint = ADR amendment, NOT story-execution event.
- The pure-transaction lint is its own small Vitest target; integrate it into `bun run check` so CI gates it. Per FR6: rejects fields named `prompt` / `confirm` and any field with `format: "tty-interactive"`.
- The `implementation.wasm` fp pattern is `^[0-9a-f]{64}$` — generators consuming this MUST treat it as content-addressing per TC8 (Epic 5's host resolves the fp to bytes; THIS story does not implement resolution).
- Per IC2: the manifest's `effects.kind: ActionEnvelope` projects to invocations whose payloads serialize to the existing signed-action envelope shape — NO new top-level fields on the envelope.

## Scope Boundaries
- This story DOES: author the action-manifest section of `schemas/memory-palace-0.1.0.json` for all 5 verbs; ship the Valibot closed-set validator (via codegen); ship the pure-transaction lint Vitest; refresh the pin.
- This story does NOT: project to CLI (Story 3.2–3.5); project to TS client / MCP (Epic 4); ship wasm action implementations (Epic 5); modify CLI dispatch yet (`src/cli/palace*.zig` stays hand-written until Story 3.5).
