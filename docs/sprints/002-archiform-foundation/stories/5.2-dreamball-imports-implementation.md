# Story 5.2: Implement 5 `dreamball.*` Imports + Per-Import Tests + Structured Event Emission

**User Story**: As an archiform author, I want the wasm host to expose exactly the 5 sprint-002-locked `dreamball.*` imports (`fp`, `encode_cbor`, `read_node`, `emit_action_envelope`, `now_ms`) with per-import tests and structured invocation event emission, so that guest wasm modules have a complete, observable, locked host-import surface to call against.
**FRs**: FR11, FR10
**Decisions**: D-020 (wasm runtime), D-022 (bridge pattern composed by `emit_action_envelope`), D-023 (signActionEnvelope cross-epic seam — see Cross-Epic Dependency below), D-032 (single shared host), D-033 (5 imports locked; addition = ADR), NFR3 (≤50ms p95), NFR11 (structured events), SEC1 (host-import whitelist), SEC2 (host-mediated signing)
**Complexity**: large
**Test Tier**: thorough

## Acceptance Criteria
- **AC1** [happy — all 5 imports exposed]: Given the production wasm host at `src/wasm-host/main.zig` (promoted from Story 5.1's spike), When a guest module imports `dreamball.fp`, `dreamball.encode_cbor`, `dreamball.read_node`, `dreamball.emit_action_envelope`, `dreamball.now_ms`, Then all 5 link successfully at module instantiation; no other `dreamball.*` names resolve.
- **AC2** [happy — per-import tests per FR11]: Given each import, When per-import test guest modules under `tests/wasm/imports/{fp,encode_cbor,read_node,emit_action_envelope,now_ms}/` are run against the host, Then each test passes — exercising at least: the happy-path call, type marshalling between guest CBOR and host Zig types, and the error semantics declared in `docs/dreamball-imports.md` (the doc itself lands in Story 5.5; the error semantics are defined in code in this story).
- **AC3** [happy — `dreamball.fp` correctness]: Given a guest call `dreamball.fp(bytes_ptr, bytes_len)`, When the host computes blake3 over the named slice, Then the returned 32-byte fp byte-equals `blake3(bytes)` computed by the canonical Zig blake3 routine; identity test against `src/blake3.zig` (or equivalent).
- **AC4** [happy — `dreamball.emit_action_envelope` composes bridge pattern + invokes signActionEnvelope]: Given a guest call `dreamball.emit_action_envelope(value_ptr)`, When the host processes it, Then: (i) host writes the envelope to a per-invocation staging area (per D-022), (ii) host calls Epic 6's `signActionEnvelope(keypair_bytes, payload_bytes)` export to produce the signature (per D-023 cross-epic seam), (iii) host promotes staging on success, (iv) returned envelope bytes carry the real Ed25519 signature; guest cannot bypass signing per SEC2.
- **AC5** [edge — `dreamball.now_ms` monotonicity]: Given two consecutive guest calls to `dreamball.now_ms()`, When timestamps are compared, Then the second is ≥ the first (monotonic clock source on the host side).
- **AC6** [perf — invocation latency per NFR3]: Given a trivial action invocation (load cached module + invoke entry + emit one signed envelope via AC4 path), When measured 100 times, Then p95 ≤ 50 ms on the M-series Mac baseline; CI publishes the measured value.
- **AC7** [structured events per NFR11]: Given any wasm action invocation, When the invocation completes, Then a structured-log JSON event is emitted on stderr containing: `action_name`, `actor_fp`, `archiform_fp`, `module_fp`, `duration_ms`, `emit_count`, `outcome` (`ok` | `trap` | `import_violation` | `fp_mismatch`).
- **AC8** [grep audit — surface locked to 5]: Given the production host source, When `grep -E '(?:^|[^a-z_])dreamball\\.(?!fp|encode_cbor|read_node|emit_action_envelope|now_ms)' src/wasm-host/` runs, Then results are zero — no 6th import has crept in (per D-033). If a 6th IS needed, the story raises a blocker (per `feedback_dreamball_ac_scope_retreat`) for ADR amendment, NOT a silent addition.

## Technical Notes
- **Cross-epic dependency on Epic 6**: `dreamball.emit_action_envelope` (AC4) calls into Epic 6's `signActionEnvelope` export on `jelly.wasm`. Epic 6 Story 6.1 (the export) MUST land before this story's AC4 can pass. Phase 3 sequencing: dispatch Story 6.1 BEFORE this story; if scheduling forces parallel execution, the spike (Story 5.1) may stub signing internally with a clearly-marked TODO_SIGNATURE_SENTINEL byte sequence, but THIS story's AC4 requires the real signing path to be wired.
- Per D-033: locked to exactly 5 imports for sprint-002. Mid-sprint discovery of a missing import = blocker (per `feedback_dreamball_ac_scope_retreat`), resolution = architecture amendment (new ADR D-NNN), NOT silent addition.
- Per SEC1: imports outside `dreamball.*` are rejected — Story 5.3 owns the failure-path AC for that; this story implements the 5 happy-path imports.
- Per D-022: `emit_action_envelope` composes the bridge pattern via `dreamball.*` — the host's per-invocation staging area is the wasm-side analog of `src/lib/bridge/*`'s staging dir.
- Per D-032: this Zig host code MUST be source-identical for CLI and browser (browser ships in sprint-003; this story compiles only the CLI target but constrains the source for future browser compilation).
- Type-marshalling: the guest passes pointers + lengths; the host reads guest linear memory directly (per WebAssembly + WASI conventions). Document the marshalling convention inline in each import's host-side Zig source (Epic 7 lifts this into `docs/dreamball-imports.md`).

## Scope Boundaries
- This story DOES: implement all 5 `dreamball.*` imports; ship per-import tests; emit NFR11 structured events; verify NFR3 perf budget; verify cross-epic seam to Epic 6's `signActionEnvelope`.
- This story does NOT: implement verify-before-instantiate / import-violation / memory-limit failure paths (Story 5.3); ship sample `mint.wasm` end-to-end (Story 5.4); author `docs/dreamball-imports.md` (Story 5.5).
