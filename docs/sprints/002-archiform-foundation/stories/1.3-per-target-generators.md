# Story 1.3: Build Per-Target Generators (`gen_zig`, `gen_ts`, `gen_valibot`, `gen_cbor`, `gen_cypher`) with Provenance + Logging

**User Story**: As a future runtime, I want `tools/schema-gen/main.zig` to repurpose as the JSON-Schema consumer entry point and dispatch to five per-target generators that each emit provenance-headed outputs with structured logging, so that every codegen artifact carries traceable origin metadata and the generator pipeline can be observed and diffed.
**FRs**: FR1
**Decisions**: D-030 (file structure), D-018 (CBOR stays Zig), NFR9 (provenance headers), NFR10 (structured logging), NFR2 (≤5s budget), NFR8 (validate-on-publish, not validate-on-decode)
**Complexity**: large
**Test Tier**: thorough

## Acceptance Criteria
- **AC1** [happy — file structure per D-030]: Given the new `tools/schema-gen/` layout, When `ls tools/schema-gen/` runs, Then the listing contains exactly `main.zig`, `gen_zig.zig`, `gen_ts.zig`, `gen_valibot.zig`, `gen_cbor.zig`, `gen_cypher.zig`, and `legacy/` (legacy is preserved during shadow phase per Story 1.4); no other top-level files in the new generator surface.
- **AC2** [happy — generation runs]: Given `schemas/root-2.0.0.json` + its pin from Story 1.2, When `bun run codegen` runs, Then `main.zig` reads the schema, verifies the pin, dispatches to all five generators in deterministic order, and writes outputs to `src/lib/generated/{types,schemas,cbor,cbor.test}.ts` plus `src/memory-palace/schema.cypher` (Cypher target wired but generates only root-level entries until Epic 2 adds the Memory Palace archiform schema).
- **AC3** [provenance headers per NFR9]: Given any generated file, When the file is read, Then the first line(s) contain a comment block naming: source schema fp (matches `schemas/.pins/root-2.0.0.fp`), schema semver (`2.0.0`), generator binary fp or commit SHA, and a `DO NOT EDIT — generated` banner.
- **AC4** [structured logging per NFR10]: Given a `bun run codegen` invocation, When stderr is captured, Then a structured-log JSON line is emitted per phase: `{phase: "schema-read", path, fp}`, `{phase: "generator-dispatch", target, schema_fp}`, `{phase: "output-written", path, bytes}`, and (in `--verify` mode) `{phase: "byte-equivalence", path, status: "match"|"diff", diff_summary}`.
- **AC5** [perf — NFR2 budget]: Given a clean checkout, When `bun run codegen` is timed three consecutive runs, Then the median runtime is ≤ 5 s on the M-series Mac baseline; CI publishes the measured time as part of the structured-log output.
- **AC6** [error — pin mismatch surfaces in logs]: Given a tampered schema (one byte changed), When `bun run codegen` runs, Then `main.zig` exits non-zero before generator dispatch; the structured log emits `{phase: "pin-verify", status: "mismatch", expected, actual}`.
- **AC7** [grep audit — no hand-decode]: Given the generated TypeScript outputs, When `grep -R 'Valibot.parse\|safeParse' src/lib/generated/` runs, Then results are zero — generated decoders do NOT call Valibot at decode time (NFR8: validate-on-publish, not validate-on-decode).

## Technical Notes
- Per D-030 Option A: rename existing `tools/schema-gen/main.zig` to `tools/schema-gen/legacy/main.zig` as the FIRST commit in this story; the new `main.zig` starts as a stub that delegates to legacy until per-target generators come online. This preserves bisectability throughout.
- Each per-target generator is a Zig module exporting a single `pub fn generate(allocator, schema, out_dir) !void`; `main.zig` orchestrates.
- CBOR codec emission (per D-018) defers to the canonical Zig CBOR encoding routines — `gen_cbor.zig` emits TS shims that call into the WASM `encode_cbor` primitive, NOT a re-implementation in TS.
- Structured-log lines go to stderr (one JSON object per line) so stdout stays usable for output-path lists if needed by future tooling.
- Provenance header text MUST be deterministic — the generator binary fp / commit SHA is the only variable; embed it via a `comptime` value populated by `build.zig`.

## Scope Boundaries
- This story DOES: ship the new `main.zig` + 5 per-target generators + provenance + logging + pin verification + the perf assertion.
- This story does NOT: delete legacy (Story 1.5); run shadow-diff CI gating (Story 1.4); author per-archiform schemas (Epic 2); generate Memory Palace–specific Cypher entries (Story 2.2).
