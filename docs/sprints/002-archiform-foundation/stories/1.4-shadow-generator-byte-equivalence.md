# Story 1.4: Shadow-Generator Phase + Byte-Equivalence CI Gate

**User Story**: As a CI gate, I want the legacy generator and the new JSON-Schema-driven generator to run side-by-side emitting to `src/lib/generated/` and `src/lib/generated.legacy/` respectively, with a byte-equivalence test diffing the two trees on every PR, so that NFR1 (the binary gating constraint) is verified continuously and the cutover commit (Story 1.5) is provably safe.
**FRs**: FR14, FR1
**Decisions**: D-030 (shadow phase file structure), NFR1 (byte-equivalence), TC1 (zero wire-format change), TC2 (all CI gates green), IC4 (sprint-001 instance compat)
**Complexity**: medium
**Test Tier**: thorough

## Acceptance Criteria
- **AC1** [happy — both generators run]: Given the new generator from Story 1.3 + the legacy generator preserved at `tools/schema-gen/legacy/main.zig`, When `bun run codegen` runs, Then both generators execute (new writes to `src/lib/generated/`; legacy writes to `src/lib/generated.legacy/`); both targets are populated with their respective outputs; the structured log emits a `{phase: "shadow-run", new_target, legacy_target}` line.
- **AC2** [happy — byte-equivalence per NFR1]: Given both target trees populated, When `tests/codegen/byte-equivalence.test.ts` (or `zig build byte-equivalence`) runs, Then `diff -r src/lib/generated/ src/lib/generated.legacy/` returns empty (exit code 0); test passes.
- **AC3** [edge — documented semantically-equivalent diffs]: Given a known cosmetic diff (e.g., comment-block ordering, whitespace within type-printf), When the byte-equivalence test runs, Then the test EITHER passes after a deterministic-formatter normalization step, OR fails with the diff captured verbatim plus a "register normalization at `tests/codegen/normalizations/<name>.md`" guidance message; no silent diff acceptance (per `feedback_dreamball_ac_scope_retreat`).
- **AC4** [error — sprint-001 instance compat]: Given a sprint-001 sample envelope captured in `tests/fixtures/sprint-001-instances/*.jelly`, When the new generator's CBOR codec decodes it, Then the in-memory representation byte-matches the legacy generator's decode of the same fixture (per IC4); test fails on any drift.
- **AC5** [CI gate — every PR]: Given a PR that touches `src/lib/generated/`, `tools/schema-gen/`, or `schemas/`, When CI runs, Then the byte-equivalence test is REQUIRED-status; merge blocked on failure. Wired into `.github/workflows/ci.yml`.
- **AC6** [happy — all 7 gates remain green at every commit]: Given each commit in the FR1 → FR4 sequence, When the full gate set runs locally (`zig build test`, `zig build smoke`, `bun run check`, `bun run test:unit -- --run`, `scripts/cli-smoke.sh`, `scripts/server-smoke.sh`, `tests/e2e-cryptography.sh`), Then all gates green per FR14 acceptance.

## Technical Notes
- The shadow phase is intentionally noisy in `src/lib/generated.legacy/` — that directory's existence in the repo is the visible signal that we're mid-migration. It is deleted in Story 1.5.
- `tests/codegen/byte-equivalence.test.ts` should use Node's `fs.readdirSync` recursively + per-file `Buffer.equals`; reading bytes (NOT parsed JSON) is the whole point.
- Add `src/lib/generated.legacy/` to `.gitignore`? No — commit it during the shadow phase so reviewers can see the legacy outputs at any commit. Removed in cutover.
- Sprint-001 fixture envelopes live in `tests/fixtures/sprint-001-instances/`; if they don't exist yet, capture them once at story start using `jelly` from a sprint-001 git tag.
- Per `feedback_full_gate_verification`: the full 7-gate run is the AC6 requirement; `bun run test:unit` alone is INSUFFICIENT for AC6 verification.

## Scope Boundaries
- This story DOES: stand up the dual-emit pipeline; ship the byte-equivalence test; wire the CI gate; capture sprint-001 fixtures; document any normalizations under `tests/codegen/normalizations/`.
- This story does NOT: delete legacy (Story 1.5 — cutover commit); add Memory Palace per-archiform schema (Epic 2); ship action-manifest changes (Epic 3+).
