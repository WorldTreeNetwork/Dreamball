# Story 1.2: Author `schemas/root-2.0.0.json` + Pin File Format

**User Story**: As an archiform author, I want `schemas/root-2.0.0.json` to fully express the current Zig root type system in JSON Schema draft 2020-12 with a deterministic blake3 pin recorded at `schemas/.pins/root-2.0.0.fp`, so that all downstream codegen consumers have one canonical, fp-pinned source of truth for root field shapes.
**FRs**: FR2, FR14
**Decisions**: D-018, D-029 (pin file format), D-035 (closed sets honored at root level where applicable), TC3 (draft 2020-12), TC6, TC8, IC4
**Complexity**: medium
**Test Tier**: thorough

## Acceptance Criteria
- **AC1** [happy]: Given the spike outcome from Story 1.1 has confirmed Assumption #1, When `schemas/root-2.0.0.json` is authored covering `Envelope`, `SealedBody`, `Signature*`, `Fingerprint`, and every other root type currently expressed in `src/protocol_v2.zig`, Then a snapshot test (`tests/codegen/root-schema-coverage.test.ts`) verifies every Zig root type has a corresponding JSON Schema entry — no field omitted.
- **AC2** [pin format per D-029]: Given the authored `schemas/root-2.0.0.json`, When `bun run schemas:pin schemas/root-2.0.0.json` writes `schemas/.pins/root-2.0.0.fp`, Then the pin file contains exactly the hex-encoded blake3 of the schema bytes as-vendored (LF line endings preserved; no trailing newline normalization), one line, no other content.
- **AC3** [draft 2020-12 compliance]: Given the schema, When validated against the JSON Schema draft 2020-12 metaschema, Then validation passes with zero errors.
- **AC4** [error — pin mismatch fails build]: Given the pin file, When the schema is mutated by one byte and `bun run codegen` runs, Then the build fails with a structured error naming the schema path, the expected pin, the computed blake3, and exits non-zero before any generator dispatches (per D-029 §Consequences).
- **AC5** [error — missing root field]: Given a Zig root type field that is NOT represented in `schemas/root-2.0.0.json`, When `tests/codegen/root-schema-coverage.test.ts` runs, Then the test fails naming the missing field; CI rejects the commit.
- **AC6** [PROTOCOL.md pointer]: Given the authored schema, When `docs/PROTOCOL.md` is reviewed, Then it contains a pointer to `schemas/root-2.0.0.json` as the authoritative shape source per FR2 acceptance (the prose change for FR15 lands in Epic 7; this AC ensures the pointer line is present).

## Technical Notes
- Schema file is pure data — no executable logic. Hand-authored from `src/protocol_v2.zig` (and the spike's hand-authored fragments from Story 1.1, lifted in).
- Pin format per D-029 Option A: plain text, single line, hex-encoded blake3, no trailing newline — pin computes blake3 over the file as-vendored which IS the canonical form (no chicken-and-egg).
- `bun run schemas:pin <path>` is a small Bun script wrapping the existing blake3 primitive (already exposed in jelly.wasm); add the script under `scripts/schemas-pin.ts` and wire it to `package.json`.
- Provenance headers (NFR9) are NOT generated for the schema itself — the schema is the source, not an output. The pin IS the schema's identity marker.
- Recrypt naming inheritance (TC9): every type name in the schema MUST match its recrypt-aligned name verbatim; reviewer confirms against `../recrypt/docs/wire-protocol.md`.

## Scope Boundaries
- This story DOES: ship `schemas/root-2.0.0.json`, ship `schemas/.pins/root-2.0.0.fp`, ship `bun run schemas:pin`, ship the coverage snapshot test, add the PROTOCOL.md pointer line.
- This story does NOT: build the per-target generators (Story 1.3); run shadow phase (Story 1.4); cut over (Story 1.5); add the full PROTOCOL.md prose updates (Epic 7); add per-archiform schemas (Epic 2).

### Completion Notes per AC

- **AC1 (root coverage)**: `schemas/root-2.0.0.json` ships 38 `$defs` entries spanning every Zig struct + closed-enum in `src/protocol.zig` + `src/protocol_v2.zig`. The spike's three schemas (`envelope`, `sealed-body`, `signature-tier-wrapper`) are lifted in as `DreamBall`, `Relic`, `SignatureTierWrapper` `$defs`. The discriminated-union over `type × 7 variants` (Spike Gap 1) is encoded as a closed enum with the per-variant attribute surface flattened on `DreamBall.properties`; per-variant `oneOf` narrowing is a Story 1.3 generator concern per spike findings. Coverage test asserts every Zig struct has a corresponding `$defs` entry (modulo the recrypt-aligned alias `Signature → SignatureTierWrapper` per TC9) and every Zig field name appears as a property name (snake_case → kebab-case wire form).
- **AC2 (pin format)**: `schemas/.pins/root-2.0.0.fp` is exactly 64 bytes — the lowercase hex blake3 of the schema bytes as-vendored — with NO trailing newline. Verified via `wc -c` (64) and `xxd` (last byte 0x63, `c`). The pin script (`scripts/schemas-pin.ts`) reads the schema byte-for-byte, hashes via the existing `jelly.wasm` `hashBlake3` export (sprint-001 surface, reused), and writes the digest with `writeFileSync(path, hex)` — Bun does NOT append a newline.
- **AC3 (draft 2020-12 metaschema)**: Validated via Ajv 2020 (`ajv@^8` added as devDep). Test case `tests/codegen/root-schema-coverage.test.ts > root schema metaschema validity (AC3)` invokes `new Ajv2020({ strict: false, allErrors: true }).compile(schema)` and asserts no throw. `strict: false` is required because Ajv's strict mode rejects unknown `x-*` keywords; per spike commitment these extension keys are valid JSON Schema (extension keywords are explicitly allowed by the spec).
- **AC4 (pin mismatch fails build)**: `bun run codegen` is now `bun run scripts/schemas-verify.ts && zig build schemagen`. The verify script blake3-hashes every `schemas/*.json` and compares against the pin; mismatch → structured error (schema path, pin path, expected, computed, reason) → exit 1. Verified by appending one byte to `schemas/root-2.0.0.json` and running `bun run codegen`: command exits non-zero with the expected/computed pair printed, BEFORE `zig build schemagen` dispatches.
- **AC5 (missing field detection)**: `tests/codegen/root-schema-coverage.test.ts` extracts every Zig struct from `src/protocol.zig` + `src/protocol_v2.zig` via a brace-depth-aware mini-parser. For each struct, it asserts every field name (kebab-cased) appears as a property name somewhere in the schema. Per-test failure messages name the missing struct + field. The test uses two whitelist hooks (`NON_ROOT_STRUCTS`, `NON_WIRE_FIELDS`) for documented exemptions; the only non-trivial entry is `LookupEntry` (lives as `$defs/MemoryNodeLookupEntry` because it's a Zig sub-type within MemoryNode).
- **AC6 (PROTOCOL.md pointer)**: Single line added at the top of `docs/PROTOCOL.md`:
  > **Authoritative shape source:** [`schemas/root-2.0.0.json`](../schemas/root-2.0.0.json) — JSON Schema draft 2020-12; pinned at [`schemas/.pins/root-2.0.0.fp`](../schemas/.pins/root-2.0.0.fp) (FR2, sprint-002 D-018 + D-029). Full prose refresh lands in Epic 7 / Story 7.1.
