# Story 6.1: Add `signActionEnvelope` Export to `jelly.wasm`

**User Story**: As a future runtime (and as Epic 5's wasm action host), I want `jelly.wasm` to export `signActionEnvelope(keypair_bytes, payload_bytes) → ed25519_sig_bytes` producing real Ed25519 single signatures, with `jelly.wasm`'s size budget (TC5: ≤200 KB raw / ≤64 KB gzipped) holding after the export is added, so that the cross-epic seam to Epic 5's `dreamball.emit_action_envelope` (D-023) is wired and the sentinel substitutions are unblocked.
**FRs**: FR13
**Decisions**: D-023 (signActionEnvelope export; Ed25519-only single sigs sprint-002), D-025 (cross-epic contract locked here), SEC3 (real Ed25519, not sentinels), SEC6 (PQ explicitly deferred per project memory), TC5 (size budget)
**Complexity**: small
**Test Tier**: smoke (with mandatory full-gate verification per `feedback_full_gate_verification`)

## Acceptance Criteria
- **AC1** [happy — export added]: Given `src/wasm_main.zig`, When `zig build wasm` produces `src/lib/wasm/jelly.wasm`, Then a new export `signActionEnvelope` is present (verified via `wasm-tools` or equivalent dump) with signature `(keypair_bytes_ptr, keypair_bytes_len, payload_bytes_ptr, payload_bytes_len) → sig_bytes_ptr` (using the existing packed-ptr-len convention from sprint-001's WASM exports per `src/lib/wasm/loader.ts`).
- **AC2** [happy — Ed25519 KAT]: Given a known-answer test vector (Ed25519 keypair + payload + expected signature), When `verifyEd25519(pk, payload, signActionEnvelope(keypair, payload))` runs through the WASM boundary, Then it returns `true`; the produced signature byte-equals the KAT expected signature.
- **AC3** [edge — bit-flipped payload fails verification]: Given the keypair, When `signActionEnvelope` signs payload P then payload `P with byte 0 bit-flipped`, Then the two signatures differ; verifying signature(P) against `P with byte 0 bit-flipped` returns `false`.
- **AC4** [TC5 — size budget holds]: Given the new `jelly.wasm`, When `stat` + `gzip` measure it, Then raw size ≤ 204800 bytes AND gzipped size ≤ 65536 bytes (per TC5); CI fails the commit on excess (this assertion already exists per sprint-001 Story 1.1 AC4 — verify it still gates).
- **AC5** [happy — cross-runtime invariant preserved]: Given the new `jelly.wasm`, When the import table is dumped, Then exactly one host import exists — `env.getRandomBytes` (no new host imports per the cross-runtime invariant; signing uses Zig's in-tree Ed25519 primitive which uses the existing randomness import).
- **AC6** [happy — Ed25519-only per SEC6]: Given the export, When the implementation is reviewed, Then it produces ONLY a single Ed25519 signature — NO ML-DSA-87 dual-sig (deferred per SEC6 + project memory `project_dreamball_pq_deferred`); no PQ key material is touched.
- **AC7** [happy — full gate set green per `feedback_full_gate_verification`]: Given the new export, When the full gate set runs (`zig build test`, `zig build smoke`, `bun run check`, `bun run test:unit -- --run`, `scripts/cli-smoke.sh`, `scripts/server-smoke.sh`, `tests/e2e-cryptography.sh`), Then all 7 gates pass — narrow tests are insufficient per project memory.

## Technical Notes
- Per D-023: this export is consumed by Epic 5 Story 5.2 AC4 (`dreamball.emit_action_envelope` host implementation). Phase 3 sequencing: Story 6.1 SHOULD land before Story 5.2 begins; if scheduling forces parallel, Story 5.2's spike (5.1) may stub signing internally with a clearly-marked TODO_SIGNATURE_SENTINEL. THIS story closes the seam.
- Per SEC6: PQ + key custody explicitly deferred. DO NOT introduce ML-DSA-87 here; substituting Ed25519-only with sentinels-removed is the sanctioned target.
- Reuse the existing Ed25519 primitive in the Zig core (already in scope per `requirements.md` Existing Codebase Inventory: "signing primitives exist; the missing piece is the `signActionEnvelope` export").
- The packed-ptr-len convention is documented in sprint-001 stories — match it verbatim. Do NOT introduce a new ABI convention.
- Per `feedback_dreamball_ac_scope_retreat`: if a hard primitive blocker emerges (e.g., the Ed25519 sign routine isn't WASM-exportable), raise the blocker — do NOT silently substitute a sentinel.

## Scope Boundaries
- This story DOES: add the `signActionEnvelope` export + KAT + tamper test + size budget verification + full-gate run.
- This story does NOT: migrate the sentinel call sites (Story 6.2); add ML-DSA-87 / PQ dual-sig (deferred per SEC6); modify any signature-bag formats (frozen per IC2); change the `env.getRandomBytes` import.
