# Story 6.2: Migrate `oracle.ts oracleSignAction` + `store.recordTraversal` to Real Ed25519 Signatures + Negative Test + Update `docs/known-gaps.md`

**User Story**: As a Dreamball maintainer, I want both derived-fp sentinel call sites in `oracle.ts oracleSignAction` and `store.recordTraversal` migrated to consume Story 6.1's `signActionEnvelope` export (producing real Ed25519 single signatures over the canonical action payload), with a negative test confirming forged signatures fail verification and `docs/known-gaps.md` updated to mark the "scope substitution" debt closed, so that the silent-substitution regression class from sprint-001 S4.4 / S5.5 is closed and no `_sentinelFp` / derived-fp / placeholder bytes remain in any signature-emitting path.
**FRs**: FR13
**Decisions**: D-022 (bridge boundary preserved), D-023 (signActionEnvelope consumed here), D-025, SEC3 (real Ed25519), SEC6 (Ed25519-only — no PQ), TC2 (full gate set)
**Complexity**: small
**Test Tier**: smoke (with mandatory full-gate verification per `feedback_full_gate_verification`)

## Acceptance Criteria
- **AC1** [happy — `oracleSignAction` migrated]: Given Story 6.1's `signActionEnvelope` export, When `src/lib/oracle.ts oracleSignAction` is rewritten, Then it computes the canonical payload, calls `signActionEnvelope(keypair, payload)` via the WASM loader, and embeds the returned 64-byte Ed25519 signature in the envelope; no `_sentinelFp`, `derived-fp`, or placeholder bytes remain anywhere in the function or its dependencies.
- **AC2** [happy — `recordTraversal` migrated]: Given the same export, When `src/memory-palace/store.*.ts recordTraversal` is rewritten (both `store.server.ts` and `store.browser.ts` if both contain the substitution), Then both compute real Ed25519 signatures via `signActionEnvelope`; same-no-substitution audit applies.
- **AC3** [grep audit — no sentinel substitution remnants]: Given the post-migration tree, When `grep -RE '_sentinelFp|derivedFp.*sign|sentinel.*sig|TODO[_ -]?CRYPTO.*sign' src/ --include='*.ts'` runs, Then results are zero — no sentinel substitution remains in any signature-emitting path (per FR13 acceptance + SEC3).
- **AC4** [error — negative test on forged signature]: Given a recorded traversal envelope produced by AC2, When the test at `tests/crypto/forged-signature.test.ts` mutates the signature bytes (bit-flip byte 0) and re-verifies via `verifyEd25519`, Then verification returns `false`; the verifier surfaces a structured error event; without forging detection, AC4 fails CI.
- **AC5** [happy — bridge pattern preserved per D-022]: Given the migrated call sites, When invoked with `JELLY_BRIDGE_DEBUG=1`, Then the bridge-pattern trace is unchanged from pre-migration (staging → bridge → promote sequence intact); signing happens within the bridge boundary, not bypassing it.
- **AC6** [happy — `docs/known-gaps.md` updated]: Given the migration, When `docs/known-gaps.md` is reviewed, Then the "scope substitution" entry's status is flipped to CLOSED with a citation to this story; the PQ dual-sig debt remains OPEN under the security-pass section (SEC6 deferral preserved).
- **AC7** [happy — full gate set green per `feedback_full_gate_verification`]: Given the migration, When the full gate set runs (`zig build test`, `zig build smoke`, `bun run check`, `bun run test:unit -- --run`, `scripts/cli-smoke.sh`, `scripts/server-smoke.sh`, `tests/e2e-cryptography.sh`), Then all 7 gates pass — narrow tests are insufficient for this fix class per project memory.
- **AC8** [happy — sprint-001 "scope substitution" regression class closed]: Given the migration, When the broader audit sweep (extending AC3 across the codebase) runs, Then no sentinel-substitution pattern exists for ANY signature-emitting path; per FR13 acceptance: "no `_sentinelFp` / derived-fp / placeholder bytes remain in any signature-emitting path."

- The keypair source is the Bun-side oracle context; how it reaches the WASM boundary is a copy-bytes-into-wasm-memory operation per the existing loader convention. Document any new copy path inline (not a new bridge primitive).
- Per SEC6 + project memory `project_dreamball_pq_deferred`: do NOT re-introduce ML-DSA-87 dual-sig sentinels as a follow-on. Ed25519-only is the sanctioned target.
- Per IC2: signature-bag changes are frozen — the bag's shape stays as-is; only its CONTENTS migrate from sentinel to real bytes.
